# Урок 1. Перший виклик LLM API: system prompt, messages, токени, вартість

## Мета
Після уроку ти викликаєш LLM напряму з коду, розумієш, з чого складається запит, і можеш порахувати, скільки коштуватиме бот клієнта на місяць.

## Теорія

### 1. Будова запиту
- **model**: яка модель (швидка й дешева чи розумна й дорожча);
- **system**: роль і правила («Ти адміністратор стоматології. Відповідай коротко...»);
- **messages**: історія діалогу (`user` / `assistant` по черзі);
- **max_tokens**: максимальна довжина відповіді.

Модель **не пам'ятає** попередніх запитів. Щоб бот «пам'ятав» розмову, ти щоразу надсилаєш історію в `messages`.

### 2. Токени
Модель рахує текст у токенах (шматках слів). Українська займає більше токенів, ніж англійська. Платиш за **вхідні** (system + історія + питання) і **вихідні** (відповідь) токени. Вихідні дорожчі.

### 3. Вибір моделі для бізнесу
- Класифікація заявок, витяг полів, прості відповіді → найдешевша швидка модель (рівень Haiku).
- Агент з інструментами, складні діалоги → середня або старша модель (рівень Sonnet / Opus).
- Актуальні назви моделей і ціни завжди перевіряй у документації провайдера: вони змінюються.

## Приклади

Встанови: `pip install anthropic python-dotenv`. У `.env`: `ANTHROPIC_API_KEY=...` (ключ з console.anthropic.com; API оплачується окремо від підписки Claude).

```python
import anthropic
from dotenv import load_dotenv
load_dotenv()

client = anthropic.Anthropic()  # сам бере ANTHROPIC_API_KEY з середовища

msg = client.messages.create(
    model="claude-haiku-5-5",
    max_tokens=300,
    system="Ти адміністратор стоматологічної клініки «Посмішка». "
           "Відповідай коротко, ввічливо, українською. Ціни не вигадуй.",
    messages=[{"role": "user", "content": "Скільки коштує чистка зубів?"}],
)

print(msg.content[0].text)
print("Вхідні токени:", msg.usage.input_tokens)
print("Вихідні токени:", msg.usage.output_tokens)
```

Діалог з пам'яттю — це просто довший список messages:
```python
history = [
    {"role": "user", "content": "Мене звати Олег"},
    {"role": "assistant", "content": "Приємно познайомитись, Олеже!"},
    {"role": "user", "content": "Як мене звати?"},
]
```

## Практика

**Завдання 1.** Отримай API-ключ, збережи його в `.env` і виконай приклад.

**Завдання 2.** Задай 5 різних питань «клієнта клініки». Чи вигадує модель ціни? Покращ system prompt так, щоб на питання про ціну бот пропонував уточнити в адміністратора.

**Завдання 3.** Зроби консольний чат: цикл `input()`, історія накопичується в `messages`. Перевір, що бот пам'ятає твоє ім'я.

**Завдання 4.** Порахуй: клініка має 50 діалогів на день, у середньому 2 000 вхідних і 300 вихідних токенів на діалог. Візьми ціну обраної моделі з офіційної сторінки цін і порахуй вартість на місяць.

## Контрольні запитання
1. Що йде в `system`, а що в `messages`?
2. Модель «забула», що клієнт назвав своє ім'я 3 повідомлення тому. Чому так буває?
3. Чому довгий діалог стає дорожчим з кожним повідомленням?
4. Яку модель взяти для сортування 10 000 листів за категоріями, і чому?
5. Чому в system prompt пишуть «ціни не вигадуй»?

<details>
<summary>Відповіді</summary>

1. У `system` роль, правила і контекст бізнесу. У `messages` сам діалог.
2. Модель не має пам'яті між запитами. Ти не передав це повідомлення в історії (або обрізав історію).
3. Щоразу надсилається вся історія, тож кількість вхідних токенів росте.
4. Найдешевшу швидку модель: задача проста, а обсяг великий.
5. Без обмеження модель може «галюцинувати» правдоподібні, але неправильні дані. Для бізнесу це прямі втрати й скарги.
</details>
