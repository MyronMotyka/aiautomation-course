# Урок 1. Перший репозиторій: init, add, commit, log, .gitignore

## Мета
Після уроку кожен твій проєкт під Git: ти бачиш історію змін і завжди можеш повернутися до робочої версії, навіть якщо Claude Code переписав пів проєкту.

## Теорія

### 1. Що таке Git
Git — це «машина часу» для папки. Кожен **коміт** — знімок усіх файлів у певний момент з описом, що змінилось.

### 2. Три зони
1. **Робоча папка**: файли, які ти редагуєш.
2. **Staging** (`git add`): що увійде в наступний знімок.
3. **Репозиторій** (`git commit`): збережені знімки.

### 3. .gitignore
Список того, що Git ігнорує: `.env` (секрети), `.venv/` (бібліотеки), бази даних, логи. **Секрет, який хоч раз потрапив у коміт, вважається скомпрометованим**, навіть якщо потім його видалити. Ключ доведеться перевипускати.

## Приклади

Встановлення: https://git-scm.com (Windows). Перевірка: `git --version`.

Одноразове налаштування:
```bash
git config --global user.name "Твоє Ім'я"
git config --global user.email "твоя@пошта"
```

Перший репозиторій:
```bash
mkdir practice/git-demo
cd practice/git-demo
git init
echo "# Мій проєкт" > README.md
echo ".env" > .gitignore
git status             # що змінилось
git add README.md .gitignore
git commit -m "Початок проєкту"
git log --oneline      # історія
```

Хороші повідомлення комітів пояснюють **що й навіщо**:
- погано: `fix`, `update`, `asdf`;
- добре: `Додано retry для запитів до CRM`.

## Практика

**Завдання 1.** Встанови Git, налаштуй ім'я та email.

**Завдання 2.** Створи `practice/git-demo`, ініціалізуй репозиторій і зроби перший коміт з README.

**Завдання 3.** Створи `.env` з вигаданим ключем. Переконайся через `git status`, що Git його **не бачить**.

**Завдання 4.** Зроби ще 2 коміти зі змінами в README і подивись історію через `git log --oneline`.

## Контрольні запитання
1. Що таке коміт?
2. Чим `git add` відрізняється від `git commit`?
3. Які 3 речі завжди мають бути в `.gitignore` Python-проєкту з автоматизацією?
4. Ти випадково закомітив `.env` з ключем OpenAI і запушив на GitHub. Що робити в першу чергу?
5. Навіщо Git, якщо код пише Claude Code?

<details>
<summary>Відповіді</summary>

1. Збережений знімок стану файлів з описом змін.
2. `add` додає зміни в staging (готує до знімка), `commit` зберігає знімок в історію.
3. `.env`, `.venv/`, `__pycache__/` (а також бази даних і логи).
4. Негайно відкликати (revoke) ключ у кабінеті сервісу і створити новий. Чистка історії — потім, вона не скасовує витоку.
5. Щоб бачити, що саме змінив Claude, і відкотити зміни, якщо щось зламалось.
