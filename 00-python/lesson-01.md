# Урок 1. Робоче середовище: venv, pip, requirements.txt, .env

## Мета
Після уроку ти створюєш кожен проєкт для клієнта однаково: окреме середовище, список залежностей і секрети поза кодом. Тоді проєкт запускається на будь-якому комп'ютері чи VPS за 2 хвилини, а ключі клієнта не потрапляють у GitHub.

## Теорія

### 1. Навіщо віртуальне середовище (venv)
Клієнту A потрібна бібліотека версії 1.x, клієнту B — версії 2.x. Якщо ставити все глобально, проєкти ламають один одного. **venv** — це окрема «коробка» з бібліотеками для одного проєкту.

### 2. requirements.txt
Список бібліотек проєкту з версіями. На сервері достатньо однієї команди, щоб поставити все те саме, що в тебе.

### 3. .env і секрети
API-ключі **ніколи** не пишуться в код. Вони лежать у файлі `.env`, який:
- читається програмою під час запуску;
- додається в `.gitignore`, тобто не потрапляє в Git;
- для кожного клієнта і сервера свій.

Поруч кладуть `.env.example` з назвами змінних, але без значень. Так інша людина бачить, які ключі потрібні.

## Приклади

Створення проєкту (PowerShell у Windows):
```powershell
mkdir practice\weather-bot; cd practice\weather-bot
python -m venv .venv
.venv\Scripts\Activate.ps1      # на Linux/VPS: source .venv/bin/activate
pip install requests python-dotenv
pip freeze > requirements.txt
```

Файл `.env`:
```
API_KEY=тут_твій_ключ
CITY=Kyiv
```

Файл `main.py`:
```python
import os
from dotenv import load_dotenv

load_dotenv()  # читає .env у змінні середовища

api_key = os.getenv("API_KEY")
city = os.getenv("CITY", "Kyiv")  # друге значення — за замовчуванням

if not api_key:
    raise SystemExit("Немає API_KEY у .env")

print(f"Місто: {city}, ключ завантажено: {api_key[:4]}...")
```

Встановлення на новому сервері:
```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

## Практика

**Завдання 1.** Створи проєкт `practice/weather-bot` з venv і встанови `requests` та `python-dotenv`.

**Завдання 2.** Створи `.env` з двома змінними та `main.py`, який їх читає. Перевір, що без `.env` програма зупиняється з зрозумілою помилкою.

**Завдання 3.** Створи `.env.example` (ті самі назви, без значень) і `.gitignore`, де є `.env` та `.venv/`.

**Завдання 4.** Видали папку `.venv`, створи її знову і віднови все однією командою з `requirements.txt`. Це імітація розгортання на сервері.

## Контрольні запитання
1. Що станеться, якщо два проєкти використовують різні версії однієї бібліотеки, а ти ставиш усе глобально?
2. Навіщо потрібен `requirements.txt`, і якою командою з нього все встановити?
3. Чому `.env` додають у `.gitignore`, а `.env.example` — ні?
4. Що поверне `os.getenv("X", "abc")`, якщо змінної X немає?
5. Клієнт надіслав тобі API-ключ у Telegram. Де він має опинитися в проєкті, а де не повинен з'являтися ніколи?
