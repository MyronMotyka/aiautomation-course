# Урок 1. Як ставити задачу Claude: контекст, мета, обмеження, критерій готовності

## Мета
Після уроку ти отримуєш від Claude Code робочий результат з першої-другої спроби, а не після десяти уточнень.

## Теорія

### 1. Claude не бачить твоєї голови
Claude бачить файли проєкту і твоє повідомлення. Він не знає, для якого клієнта робота, що вже пробували і що для тебе «готово». Більшість поганих результатів — це погано поставлені задачі.

### 2. Формула хорошої задачі
1. **Контекст**: що це за проєкт, для кого, що вже є.
2. **Мета**: що має з'явитися або змінитися.
3. **Обмеження**: стек, чого не чіпати, вимоги клієнта.
4. **Критерій готовності**: як перевірити, що все працює.

### 3. Великі задачі ріж на частини
«Зроби мені CRM з ботом і звітами» — погано. Краще: спершу таблиці, потім webhook, потім бот. Після кожного кроку перевіряй і роби коміт у Git.

## Приклади

Погано:
> Зроби скрипт для заявок

Добре:
> **Контекст:** клініка отримує заявки з форми на сайті. Форма надсилає POST з JSON `{name, phone, message}`.
> **Мета:** FastAPI-сервіс з ендпоінтом `/lead`, який приймає заявку і зберігає її в SQLite-таблицю `leads` з датою.
> **Обмеження:** Python 3.11, тільки FastAPI і стандартна бібліотека, секрети в `.env`. Телефон має бути у форматі +380XXXXXXXXX, інакше повертай 400.
> **Готово, коли:** є `requirements.txt`, README з командою запуску і приклад curl-запиту, який успішно створює заявку.

Корисні фрази:
- «Спершу запропонуй план, код поки не пиши».
- «Поясни, що ти змінив і чому».
- «Які крайові випадки ти не обробив?»
- «Не змінюй файли X і Y».

**Завдання 2.** Перепиши ці 2 погані промпти в хороші:

- «Виправ помилку в n8n»

**Завдання 3.** В окремій папці `practice/lead-api` дай Claude Code задачу з прикладу вище. Запусти результат і перевір критерій готовності. Запиши, скільки уточнень знадобилося.

**Завдання 4.** Попроси Claude пояснити кожен створений файл. Перекажи своїми словами, що робить головний файл.
